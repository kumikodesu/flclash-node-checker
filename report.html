综合分为各维度百分制评分乘以权重后求和。网速权重固定为 20%，参考上限为 100 Mbps；同一评分尺度用于全部节点，与当前批次最快节点无关。IPLark 为 IP 质量/信誉评分，不是网速或延迟。

网速分 = min(100, 100×ln(1+Mbps)/ln(101)) × 下载成功次数/2。下载两次取中位数，计时从响应头返回后开始，含首个数据块等待；任一次失败都会降低此项。每次采样目标上限 20 秒（加一个读超时可能稍长）；限时停止且已取得至少 256 KiB 时按实际字节和耗时计算，原始数据标记 time_limited，不把正常低速记为失败。延迟分 = 100/(1+(ms/400)^1.25)；波动分 = 100/(1+(ms/100)^1.25)。

响应延迟为 Cloudflare 同一零字节 HTTPS 端点五次新连接的响应耗时中位数，包含代理握手、TLS 和 HTTP。延迟波动为相邻成功请求耗时差的中位数，至少需要两对；这不是 ICMP ping 或实际网络丢包率。请求成功率覆盖九次请求：五次 Cloudflare、Google、Microsoft、两次 IPv4 出口查询。Microsoft 使用官方 NCSI HTTP 探针并核对正文，其他探针为 HTTPS。连通性按 Cloudflare / Google / Microsoft 三站分别计算。

IPv4 出口在下载前后各查询一次。如果发生变化，IPLark 分取所有观测出口的最低分；无法取得任一出口评分时综合分保持缺失，只展示性能部分分（上限 60）。完整分数只在数据完整的节点间排名。连接全失败的节点标记 0 分；停止后的未测节点保留为空。

通过已安装的 FlClashCore 独立临时实例和本机独立端口逐个测试，关闭测试实例 TUN。节点、证书和必要的链式引用来自当前配置快照；不修改日常 FlClash 配置、系统代理和选中节点。浏览器查询安排在测速后，避免干扰。链式节点受其依赖组选择影响，DNS 使用系统解析，结果可能与日常规则/TUN 下的表现不同。

短时下载并非长期带宽保证。不同域名、IPv6、负载均衡或不同时段可能走不同出口；这里的 IPLark 评分明确针对观测到的 IPv4 出口，不验证流媒体或 AI 服务解锁。

节点地区优先显示 IPLark 公开页面的实际出口 IP 国家/地区；多个出口地区全部列出。缺少出口地区时按节点名称中的地区代码推断，并标注“名称推断”；没有明确依据时显示“未知”。地区不参与评分。

来源：IPLark（公开页面分数；优先使用 24 小时内已核实的本地缓存，仅缺失或过期时查询实时页面，明确显示“缓存”和原查询时间；不调用付费拓展数据），Cloudflare 官方测速端点。

如果两次 IPv4 出口查询均失败、但性能探针可连接，会最多额外重试两次出口查询；重试记录和时间见原始数据，不修改原九次探针成功率。
